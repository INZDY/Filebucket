# Manga Reader Overlay and Client-Side Archive Decompression

To enable sequential image reading within Filebucket, we decided to build a fullscreen Manga Reader overlay supporting Webtoon (vertical scroll) and Paged (horizontal scroll) layouts. The reader dynamically groups loose images in a folder or, on archive uploads, extracts page images directly in the browser using `jszip` client-side, filtering out hidden system folders/files (e.g. `__MACOSX`, `.DS_Store`) and naturally sorting pages alphabetically using `compareAlphanumeric` to ensure correct sequential page flow.

Reader navigation and progress were later refined per `docs/research/reader-navigation.md`. The reader keeps its hand-rolled paging engine rather than adopting a carousel library (Swiper renders real DOM per slide, which fights long chapters, and its zoom module competes with swipe paging); Embla plus `react-zoom-pan-pinch` remain the fallback only if hand-rolled paging becomes painful. The footer now carries a numeric page jump and, in paged modes, a draggable scrubber, while the chapter filename lives in the header. Keyboard navigation covers arrows, Space/PageUp/PageDown, and Home/End, with webtoon mode scrolling instead of paging. Progress is persisted per media asset through `/api/media/progress` — the page index is stored as `position` and the layout mode under `settings.mangaLayoutMode` — mirroring how the Book Reader resumes EPUB and text files.
